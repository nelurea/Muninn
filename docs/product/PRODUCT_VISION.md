# Muninn Product Vision

Status: Draft v0.1  
Scope: プロダクトの目的・体験原則。画面仕様や技術実装を確定する文書ではない。

## 1. 目的

Muninnは、ユーザーがイラストなどの作品と出会い、鑑賞し、その体験の文脈（Context）を自然に残し、後から作品や体験を見つけ直すためのアプリである。

**作品の鑑賞が主役。Contextの入力・管理は鑑賞を豊かにする手段であって、負担にしてはならない。**

## 2. アプリを開く3つの理由

1. **新しい作品との出会い**：新作・未知の作者・好みに合う作品を見つけたい。
2. **過去の作品との再会**：以前見た／保存した好みの作品を見つけ直したい。
3. **Moodに合う鑑賞**：今の気分や求める体験に合う作品を、新規・保存済みを問わず楽しみたい。

この3つを主要な利用シナリオとして、起動・ナビゲーション・検索・推薦を設計する。

## 3. 対象コンテンツとサービス

イラスト、複数枚作品、GIF・アニメーション、動画を鑑賞・保存・検索・再鑑賞できることを目指す。

対象となる投稿元は、pixiv、ニコニコ静画、ニジエなどのイラスト投稿サービス、X、Misskey、Mastodon、個人のポートフォリオなど。サービスごとに可能な操作や取得できる情報が異なるため、対応は段階的に拡張する。

## 4. Sessionと鑑賞目的

ユーザーは、アプリを使う目的を選択・作成し、再利用できる。例：デイリー巡回、新規開拓、お気に入り再訪、R-18鑑賞、R-18G鑑賞、元気を出したい、癒やされたい、感動したい。

- 現在の目的は鑑賞中も簡単に確認・変更でき、Sessionの文脈として記録される。
- 目的に応じて作品の表示・検索・推薦を調整する。例：R-18鑑賞向けの絞り込み、新規開拓向けの既知の題材への偏りの抑制。
- 目的の選択は低摩擦にする。アイコン＋テキストのプリセット／プルダウンなどはUI案であり、仕様確定前に検証する。
- 鑑賞目的・現在のMood・センシティブコンテンツ表示ポリシーは、関係していても同じ概念として扱わない。

## 5. 保存するContext

作品の出典・作者・タグ・メディアなどの**Source Metadata**と、ユーザーの経験に属する**Personal Context**を区別する。

| 概念 | 記録する意味 |
| --- | --- |
| Session / Purpose | どのようなまとまりの活動で、何を目的に鑑賞したか |
| Mood at viewing | そのとき、どんな作品を見たい気分だったか |
| Future Mood | 将来、どんな気分のとき再鑑賞したいか |
| Situation | 鑑賞時の状況・環境 |
| Feeling | 鑑賞時に抱いていた感情 |
| Focus | 作品内のどこに注目したか |
| Reaction | 鑑賞を通じて自分に何が起きた／どう変わったか |

個々のContextがSession・作品・個別メディア・保存／鑑賞イベントのどこに属するかは、意味に応じて定義する。異なる時点の体験は上書きで失わない。

## 6. Context入力の体験原則

**Save First, Enrich Later.** 作品の表示・保存の基本体験は維持し、Context入力は任意で、後から追加・修正できる。

- **自動取得を優先**：時刻、出典、作品メタデータなどを可能な限り記録する。
- **反復入力を減らす**：Sessionの文脈、直前の選択、最近使用した候補を活用し、作品ごとに同じ入力を要求しない。
- **画像編集のように直感的にする**：Focusはペン・範囲選択、Mood／Feelingは横スクロールのフィルタ選択、Situation／Feelingは検索可能な絵文字・スタンプパレットをUIの候補とする。
- **鑑賞を妨げない**：入力のための画面遷移やフォームを最小限にし、入力せずに先へ進める。
- **原本を保護**：Focusやスタンプなどは意味を持つContextとして管理し、作品ファイルそのものの編集とは分離する。

## 7. 作品を主役にしたUI

Gallery・Discovery・再鑑賞画面では作品の表示領域を優先する。操作は見つけやすくしつつ、管理用ボタンを常時並べない。視認性、適切な余白、コントラスト、タップ領域、統一した操作規則を備えた、落ち着いたデザインを目指す。

## 8. 判断基準

新機能や設計変更は、次の問いで評価する。

1. 新しい作品との出会い、過去の作品との再会、Moodに合う鑑賞のいずれかを明確に改善するか。
2. Contextの記録価値は、入力の手間や注意の分断を上回るか。
3. 同じ情報を繰り返し入力させず、後から意味を更新できるか。
4. 既存の作品・保存履歴・文脈を失わずに実装できるか。
5. UIとコードの複雑さを不必要に増やさないか。

## 9. 未確定事項

- 起動時の目的選択を毎回求めるか、前回値から開始するか。
- 目的プリセットとMood、コンテンツ表示設定の組み合わせ方。
- Sessionの開始・終了と、保存イベント／鑑賞イベントの関係。
- Context入力UIの具体的な操作と、どの程度の自動推定を採用するか。
- 目的別の絞り込み・推薦ロジックおよびサービスごとの対応範囲。

これらは個別の設計文書・Issue・ユーザーテストで決定する。未検証のUI案をプロダクト原則として固定しない。
